Handheld console · ARM64

The system and the apps, in one place.

Giochi OS is the clean Linux base built with Buildroot, delivered as an image ready for the card. There is also a virtual machine image, to try it in QEMU without hardware. Apps live outside the image: you install them from the store, on the writable partition, and you can replace them whenever you want.

How to start in QEMU

Uncompress first:

xz -dk giochi-qemu-aarch64-0.1.3.img.xz
xz -dk giochi-qemu-aarch64-0.1.3-Image.xz
qemu-system-aarch64 \
  -M virt \
  -cpu cortex-a53 \
  -smp 2 \
  -m 512 \
  -kernel giochi-qemu-aarch64-0.1.3-Image \
  -drive file=giochi-qemu-aarch64-0.1.3.img,if=virtio,format=raw \
  -append "root=/dev/vda rw console=ttyAMA0" \
  -netdev user,id=net0 \
  -device virtio-net-device,netdev=net0 \
  -nographic

Login root, password giochi-system. To leave the console: Ctrl+A, then X. This image is headless: the console is the interface. Apps are in /opt/giochi/apps — run the launcher with SDL_VIDEODRIVER=dummy.

Check the checksum

Each device has its own checksum file, and it covers every file of that device — image, kernel and anything else published. If one does not match, the download is corrupt: download it again before writing.

1

Download the device checksum

  • powkiddy-x35h-SHA256SUMS
  • powkiddy-x55-SHA256SUMS
  • r35s-SHA256SUMS
  • qemu-aarch64-SHA256SUMS
2

Run it in the same folder as the files

sha256sum -c <device>-SHA256SUMS

Replace <device> with your device id. Every line that does not say OK is a file you cannot use.

3

Full instructions

Each device also publishes a <device>-README.txt with the step by step for that file — write it to the card or start it in the virtual machine.

Write to the SD card

Only for the SD card images. The virtual machine ones do not go on a card: uncompress them and run the command in the device card.

1

Uncompress

xz -dk giochi-*.img.xz

dd writes raw bytes. Pointing it at the .xz would write the compressed file to the card and the device would not boot. Zstd: zstd -d; gzip: gunzip -k.

2

Find the device

lsblk

The card is usually /dev/sdX or /dev/mmcblkX. Check the size: a 32 GB card shows up as about 29 GB.

3

Write

sudo dd if=giochi-*.img of=/dev/sdX \
  bs=4M conv=fsync status=progress

The card will be erased completely. conv=fsync is not optional — without it the write can be truncated.

4

Check the result

sudo e2fsck -fn /dev/sdX2

The partition number changes with the device layout — the README.txt of your device tells you which. A filesystem error here means a bad card or an interrupted write.

Run in a virtual machine

Useful to get to know the system and to test without hardware. It is not the device: without a GPU, 3D games do not open, and the serial console is the interface.

How it is made

Giochi System

Builds the clean Linux with Buildroot: kernel, rootfs, boot, drivers and panel for each device. No user interface here.

Giochi app

The apps, each one with its requirements manifest. The system compares the manifest with the device profile before installing.

Giochi games

The games, with the same manifest. They go into the image when their distribution is image; otherwise they stay in the store.

Giochi OS

Joins the three: embeds the image apps into the rootfs, checks the result inside the image and publishes it with a checksum. This page.

Why apps live outside the image

The root is signed and read-only. Apps installed in /user can be replaced by the user — including by a modified version, which is what the GPL requires of GPL software. That is why the store runs on the computer and sends the package ready, instead of embedding everything in the image.

Repositories

Independent repositories. Nothing is imported from one into another: the path comes as an argument and the only coupling is the JSON contract.

  • GIOCHI-SYSTEM — the clean Linux for each device
  • GIOCHI-APP — the apps and the store
  • GIOCHI-GAMES — the games
  • GIOCHI-OS — this repository: joins and publishes
  • All releases

Licenses

System

Giochi System is MIT licensed. Buildroot and kernel components keep their original licenses; the text of each one is inside the image, in /usr/share/licenses.

Apps and games

Proprietary license, declared in each app manifest. An app whose license is incompatible with the image is refused at packaging time — the check is here, it does not depend on another repository having run first.
